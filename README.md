# Averaged Optimal Control for Low-Thrust Secular Orbital Deployment

MATLAB scripts and utilities supporting the AAE 568 project **“Averaged Optimal Control for Low-Thrust Secular Orbital Deployment.”** The repository implements an *averaged*, indirect optimal-control framework (Pontryagin’s Minimum Principle) for long-duration, low-thrust orbital transfers using **modified equinoctial elements (MEE)**. The primary solver is an averaged Hamiltonian shooting method, with unaveraged dynamics used afterward to reconstruct Cartesian trajectories and thrust histories for analysis and plotting.

## What this repository does

- Solves low-thrust transfer/circularization problems using an averaged PMP formulation in MEE.
- Evaluates averaged Hamiltonian/costate dynamics via **Gauss–Legendre quadrature** over the fast true-longitude variable.
- Solves the resulting boundary-value (shooting) problem with nonlinear solvers (e.g., `lsqnonlin`; other scripts use `fminunc` / `fsolve`).
- Uses homotopy/continuation strategies to warm-start related shooting problems (e.g., neighboring RAAN targets; eccentric-to-circular targets).
- Reconstructs trajectories in Cartesian space after convergence for visualization (transfer path, thrust history, ground tracks, etc.).

## Method overview

- **Averaged PMP dynamics (MEE):** The state is propagated in modified equinoctial elements along with costates from PMP. The dynamics used for the shooting solve are *averaged* rather than fully unaveraged.
- **Gauss–Legendre Hamiltonian averaging:** The averaged dynamics are formed by integrating Hamiltonian-derived quantities over the fast longitude using `lgwt.m` (Legendre–Gauss nodes/weights). In the symbolic path, integrands are evaluated by generated MATLAB functions in `generated_symbolic/`.
- **Shooting + nonlinear least squares:** Terminal constraints (final element targets and transversality conditions such as select terminal costates) are enforced by solving for the initial costate vector using `lsqnonlin` in the main RAAN constellation and circularization scripts.
- **Homotopy continuation:** Several scripts perform continuation from an easier boundary condition to the desired one (e.g., RAAN stepping across satellites; eccentric-to-circular target blending via a continuation parameter).
- **Unaveraged reconstruction (post-convergence):** After solving the averaged shooting problem, trajectories are reconstructed in Cartesian space for interpretation and plotting (e.g., `prop_reconstructed_cartesian_trajectory.m`).

## Repository structure

Top-level scripts and key folders (as present in this repository):

- **Main scripts / entry points**
  - `main_sym_lsqnonlin.m` — single transfer solve using symbolic averaged dynamics + `lsqnonlin`.
  - `contellation_eccentric.m` — RAAN-distributed constellation deployment (eccentric final shape).
  - `constellation_circ.m` — post-deployment circularization of an existing constellation already in the workspace.
  - `build_symbolic_files.m` — generates symbolic integrand functions into `generated_symbolic/`.
  - Other scripts present (purpose not fully specified in-code): `main_sym_fminunc.m`, `main_fsolve.m`, `mainFD.m`, `mainWorkspace.mat`, `constellationWalker.m`.

- **Averaging / optimal-control core**
  - `Averaging Logic/` — numerical averaged dynamics and Hamiltonian evaluation utilities (e.g., `calculate_averaged_hamiltonian.m`, `lgwt.m`, and related helpers).
  - `symbolicLogic/` — symbolic averaged dynamics / Hamiltonian wrappers (e.g., `averaged_dynamics_symbolic.m`, `calculate_averaged_hamiltonian_symbolic.m`).
  - `generated_symbolic/` — autogenerated symbolic MATLAB functions (e.g., `H_unavg_sym_fun.m`, `dsHdx_integrand_sym_fun.m`, `dsHdlam_integrand_sym_fun.m`).

- **Propagation / reconstruction**
  - `propagators/` — orbit and reconstruction propagators (e.g., `prop_reconstructed_cartesian_trajectory.m`, `prop_kepler_orbit_from_mee_for_time.m`).

- **Plotting utilities**
  - `plotters/` — plotting helpers (e.g., `earthy.m`, `plotGroundTrackFromRotatingState.m`, `plotOrbit3.m`).

- **Coordinate/element conversion utilities**
  - `converters/` — Keplerian/Cartesian/MEE conversion helpers.

- **Perturbations and misc. utilities**
  - `perturbations/` — e.g., `J2pert.m`, `moonPert.m`, `noPert.m`.
  - `genTools/` — general-purpose helpers.

- **Example/result workspace files** (MATLAB `.mat`)
  - `mainWorkspace.mat`, `constellationWorkspace.mat`, `constellationWorkspace2.mat`.

## How to run

The repository is script-driven. Typical entry points:

1. **Single transfer (symbolic averaged shooting, `lsqnonlin`)**
   - Run: `main_sym_lsqnonlin.m`

2. **RAAN-distributed constellation deployment (eccentric final shape)**
   - Run: `contellation_eccentric.m`
   - Note: this script solves each satellite independently and uses the previous satellite’s optimized initial costate as the next seed.

3. **Post-deployment circularization of an existing constellation**
   - Run after a constellation deployment has populated the MATLAB workspace variables (`x_all`, `lambda_all`, `target_all`, `params`, `DU`, `TU`, `N_s`, `odeopts`, `lsqopts`):
     - `constellation_circ.m`

4. **(Optional) regenerate symbolic integrand functions**
   - Run: `build_symbolic_files.m`
   - This overwrites `generated_symbolic/*.m`.

## Outputs

The scripts primarily generate:

- Console summaries (terminal residuals, final mass, Hamiltonian drift, etc.).
- MATLAB figures including (depending on script):
  - state/costate histories vs nondimensional time,
  - residual norms and solver iteration counts,
  - \(\Delta v\) summaries/plots,
  - 3D trajectories and final orbits (inertial and Earth-rotating frames),
  - ground tracks (where used).

Persisted output files are not systematically written by scripts (beyond the included `.mat` workspaces).

## Limitations

- Uses **regular Gauss–Legendre averaging** over the fast longitude; this repository does **not** implement eclipse modeling.
- Does **not** implement focused quadrature in the main symbolic shooting workflow (a separate focused-averaging path exists in `Averaging Logic/`, but usage depends on the script).
- Does **not** solve the full **unaveraged** PMP boundary-value problem directly; unaveraged dynamics are used for reconstruction/visualization after the averaged solution converges.
